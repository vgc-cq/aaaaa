# 任务2：多维表格/数据结构设计

## 一、表结构总览

本系统共设计 **9张核心表**，覆盖完整的短视频电商业务链路。

### 表间关联关系

```
商品库(P) ──1:N──→ 内容拆解(C) ──1:N──→ 脚本分镜(S) ──1:N──→ 视频生产(V)
                                                                      │
                                                                      ↓
                                                                投流数据(A)
                                                                      │
                                                                      ↓
                                                                数据复盘(R)
                                                                      ↓
                                                                知识库(K)
```

## 三、关联关系说明

| 关联类型 | 关联表 | 关联字段 | 说明 |
|----------|--------|----------|------|
| 商品↔内容 | products ↔ contents | product_id | 一个商品可对应多个内容方向 |
| 内容↔脚本 | contents ↔ scripts | content_id | 一个内容方向可生成多个脚本 |
| 商品↔脚本 | products ↔ scripts | product_id | 直接关联商品 |
| 脚本↔视频 | scripts ↔ videos | script_id | 一个脚本可制作多个版本视频 |
| 视频↔投流 | videos ↔ ad_data | video_id | 一个视频对应一条投流数据 |
| 投流↔复盘 | ad_data ↔ reviews | ad_id | 一条投流可生成多条复盘记录 |
| 复盘↔知识 | reviews ↔ knowledge | notes 标记 | 复盘"认可"后沉淀为已生效知识 |
| 复盘↔记忆 | reviews ↔ agent_memories | review_id | 认可/不认可反馈写入经验记忆 |
| 智能体↔日志 | agent_runs | - | 每次运行写入一条运行日志 |

## 四、视图设计

### 1. 今日待处理视图
- 筛选条件：状态为"待评估"、"待跟进"、"待审核"的记录
- 按优先级排序

### 2. 按负责人看板
- 分组字段：owner/editor/analyst
- 显示每人待处理数量

### 3. 按状态看板
- 分组字段：status/publish_status/review_status
- 看板形式展示各状态分布

### 4. 复盘结果/高优先级问题视图
- 筛选条件：ROI<1 或有异常标记的投流数据
- 关联显示对应的视频和复盘建议


## 五、字段补齐说明

为满足测试题验收，每个核心表已补充状态、优先级、负责人或备注类字段；投流数据表已补充播放量、2秒跳出率、5秒完播率、完播率、用户反馈等原题复盘字段；视频表补充通义万相生成任务字段（generate_task_id / generate_status / video_url）；复盘环节新增智能体运行日志表（agent_runs）与经验记忆表（agent_memories），支撑数据复盘智能体的运行记录与"认可/不认可"反馈闭环。仪表盘提供今日待处理、负责人看板、状态看板、高优先级问题视图。
